# PROMPT-BLOCK-START
You are an expert in combinatorial optimization, scheduling, and metaheuristics.
Your mission is to design a novel and high-performing perturbation strategy for
Guided Local Search (GLS) applied to the Flow Shop Scheduling Problem (FSSP).

PROBLEM CONTEXT:
- **Task**: Design a function that updates the execution time matrix and selects
  top jobs to perturb in order to escape local optima in GLS for FSSP.
  The GLS framework alternates between local search (swap + relocate) and
  perturbation guided by your function. After perturbation, a focused local search
  is applied only to the selected jobs.
- **Function signature**: `get_matrix_and_jobs(current_sequence, time_matrix, m, n) -> (new_matrix, perturb_jobs)`
- **Inputs**:
  * `current_sequence` (list): Current sequence of job indices.
  * `time_matrix` (np.ndarray, shape (n, m)): Execution time of each job on each machine.
  * `m` (int): Number of machines.
  * `n` (int): Number of jobs.
- **Outputs**:
  * `new_matrix` (np.ndarray, shape (n, m)): Updated execution time matrix used for
    the perturbation local search step.
  * `perturb_jobs` (list): Indices of jobs to focus perturbation on.
    Must have length > 1 (at most 5 jobs will be used).
- **FSSP setup**:
  * 64 training instances with 50 jobs and 20 machines each.
  * Instance data contains processing times for each job-machine pair.
  * During evolution, 3 instances are used for evaluation (for speed).
  * GLS runs for up to 30 seconds per instance with max 1000 iterations.
  * Initial solution constructed using the NEH heuristic.

EVALUATION:
- **Fitness** (maximize): Negative of the average makespan across evaluation instances.
  Higher values (closer to 0) indicate shorter schedules.
- **avg_makespan**: Average makespan across instances (lower is better).
- **eval_time**: Total execution time in seconds.

COMPUTATIONAL RESOURCES & IMPLEMENTATION GUIDELINES:
**Core packages**: numpy
- The function is called once per GLS iteration (up to 1000 times per instance).
- Avoid expensive operations; prefer vectorized NumPy operations.
- The function should be deterministic for reproducibility.
- The returned job list must have length > 1 or evaluation fails.
- If more than 5 jobs are returned, only the first 5 will be used.

DESIGN TIPS:
- Consider which jobs contribute most to the makespan (critical path analysis).
- Modifying processing times of bottleneck jobs can help the search explore new schedules.
- Random perturbation alone is weak; use problem structure to guide perturbation.
- Consider the relationship between consecutive jobs and machine idle times.
- Selecting jobs that are adjacent on the critical path for perturbation can be effective.
- The new_matrix should be meaningfully different from the original; small changes
  may not provide enough landscape perturbation.

COMPUTATIONAL BUDGET:
- **Time limit**: 120 seconds maximum total execution time.
- **Memory limit**: 2 GB.

KNOWN BASELINES:
- NEH + local search (no GLS): high makespan, easily trapped in local optima.
- Standard GLS with random perturbation: moderate improvement.
- State-of-the-art EoH heuristics: significant makespan reduction through intelligent perturbation.
